### What init did that the plan did not expect

`init` printed an "Updating fonts" step and rewrote `app/layout.tsx`. It replaced the Bricolage Grotesque loader with `Geist({subsets:['latin'],variable:'--font-sans'})`, added `import { cn } from "@/lib/utils"`, and changed the `<html>` class to `cn("h-full", "antialiased", "font-sans", geist.variable)`. Committed as generated, the page would render in Geist. That fails this issue's own check (the `h1` still computes to Bricolage Grotesque) and the plan's one-family decision in section 4, and it would undo issue #4 from Phase 1.

The file was restored with `git checkout -- app/layout.tsx`. The issue body says "commit what it generates as-is"; that sentence was written before anyone knew `init` touched the layout, and the issue closes with this pull request, so it stays as written. The plan's facts now say what `init` does to the layout and what to do about it.

`npx shadcn@latest init --help` lists no flag that skips the font step. `--yes` defaults to true, so the command ran without a prompt.

### Review pass

**1. Error and empty states.** This sub-issue adds no UI and no runtime code; the page renders the Phase 1 placeholder unchanged. The states the change can reach are at install and compile time, and each prints its own next step:

- `npm ci` with a stale lockfile prints npm's sync error and names the mismatched package. Next step: `npm install` locally and commit the lockfile (plan section 7, Builder boot check, item 1).
- Turbopack failing to resolve `shadcn/tailwind.css` or `tw-animate-css` would print the unresolved specifier and the importing file in the dev log. The next step differs per import. For `shadcn/tailwind.css`, `npx shadcn@latest eject` inlines that file into `globals.css` and removes the `shadcn` dependency; the CLI's own help says it does that and nothing else. For `tw-animate-css`, `eject` does not help. Copy `node_modules/tw-animate-css/dist/tw-animate.css` (15 KB) into `app/`, change the import to `@import "./tw-animate.css";`, and remove the package. A deep import such as `tw-animate-css/dist/tw-animate.css` is not an option, because the package's `exports` map exposes only `.` and `./prefix`. Not reached; both resolved.
- A missing `lib/utils.ts` would fail `tsc` on the unresolved `@/lib/utils` import in whatever imports it. Nothing imports it yet.
- The generated `.dark` block is dead CSS until something puts a `dark` class on an ancestor. Nothing does, and #15 deletes the block.

Nothing leaves the user with nothing to do.

**2. Type fields rendered by the UI.** None added. `lib/utils.ts` re-exports `cn`, a function, and `components.json` is CLI configuration that the page never reads. The page still renders the same `h1` and `p`.

**3. Permission gates per route.** Not applicable. Still one static route, `/`, no service calls, no auth. `init` reached the network once, for the shadcn registry and npm, from the local terminal and not from the page.
