### Review pass

**1. Error and empty states.** The component has no data fetching, so its states are prop values. Four are reachable.

- `description` missing, `""` or whitespace only (the first version tested truthiness, so `" "` rendered an empty paragraph; the branch review caught it): the paragraph is left out and the title stands alone. Nothing for the user to do.
- `title` blank or whitespace: the issue's sketch rendered an empty `<h2>`. A screen reader user moving by headings would land on a heading with no name and have nothing to do next. **Fixed.** The `h2` is left out. The first version of this fix returned `null` for the whole block, and the branch review pointed out that someone clearing a title in the Visual Editor would then watch the description vanish too with nothing to say why. The description now stays, without its top margin, and the block returns `null` only when both strings are blank. `title` stays a required `string`, so leaving it off is still a `tsc` error.
- One very long word in the title or description: the text overflowed its box (884px of text in a 672px box at 1280px), and at phone width that becomes a sideways scroll for the whole page. **Fixed** with `break-words` on the wrapper, measured above. Ordinary titles are unaffected because the rule only applies when a word cannot fit a line.
- An `align` value outside the union: a `tsc` error naming the prop.

**2. Type fields rendered by the UI.** `SectionHeadingProps` has four fields.

| Field | Renders in |
|---|---|
| `title` | the `h2` text |
| `description` | the `<p>` under it, when not blank |
| `align` | no text of its own; `center` adds `mx-auto text-center` to the wrapper |
| `className` | no text of its own; merged last onto the wrapper |

Every field has an effect. None of them is on the live page today, because nothing imports the block until #38.

**3. Permission gates per route.** Not applicable. The site still has one static route, `/`, with no service calls and no auth. The new module reads no request API, so the route stays prerendered.

### Review pass

**1. Error and empty states.** No data fetching, so the states are prop values.

- A blank label: the sketch would render a button with no text, which a screen reader announces as a link with no name. **Fixed.** The link is left out.
- A blank href: an empty `href` points at the current page, so a visitor clicks the main call to action and lands where they started. Reasoned from how browsers resolve an empty `href`, not measured. **Fixed.** The link is left out.
- Both links unusable, or the only link unusable: the group renders nothing, so no empty flex box takes up space. The caller's wrapper margin still applies, which is how the author sees something is missing.
- A blank primary with a usable secondary: the secondary renders alone and keeps the outline style. It is not promoted to the default style, because the style says which link the author marked as secondary.
- A very long label: the button overflows a phone screen past roughly 47 characters, measured above. The visitor can still read and tap the button, and the planned labels are under half that. Left as is; see item 5.
- The outline link with no border: not an error state, but a visitor on the cream band could not tell the secondary link was a button. **Fixed** with `cn(...)`, measured above.
- A target that does not exist yet (`#pricing` until Phase 5): the hash changes and the page does not scroll. That belongs to the page, not this block, and #32 lists it under "Out of scope".
