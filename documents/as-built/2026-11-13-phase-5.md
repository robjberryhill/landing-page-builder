### The three choices the issue left open

| Choice | Used | Why |
|---|---|---|
| Blank strings | `hasText` from `lib/text.ts`. A blank `value` leaves out the value line, a blank `label` leaves out the label line, and with both blank the block returns `null`. | The same rule as `SectionHeading`, `BagLabel` and `FeatureCard`. A value cleared in the Visual Editor leaves its label standing, so the person editing can see what happened. |
| A very long word | `min-w-0 wrap-anywhere` on the wrapper | The same pair `FeatureCard`'s inline variant uses. `break-words` does not shrink a grid item, measured in Phase 4. |
| The element | Two `<p>` elements, as the plan has it | See below. |

On the element. A `<dl>` puts the term first and its value second, so a stat would be read as "roaster to porch, on average: 48 hours", with the label before the number it explains. The page shows the number first, and showing it first in a `<dl>` means reordering with CSS so that the visual order and the reading order disagree. With two paragraphs a screen reader reads "48 hours" and then "roaster to porch, on average", which is the sentence as written. The accessibility tree for the grid lists a `paragraph` for each line, value before label, in the order of the array. The driver printed the first four of the eight, and none had another role.

### Review pass

**1. Error and empty states.** The component fetches nothing, so its states are prop values. Four are reachable.

- `label` blank or whitespace: the label line is left out and the number stands alone. Nothing for the visitor to do.
- `value` blank or whitespace: the issue's sketch rendered an empty `<p>` that still took 48px of height, leaving a gap above the label. **Fixed.** The value line is left out and the label loses its top margin.
- Both blank: the sketch rendered an empty `<div>` with two empty paragraphs, a blank grid cell. **Fixed.** The block returns `null`. The grid in #44 then has one fewer child and closes the gap. Both props stay required strings, so leaving one off is a `tsc` error.
- One very long word: without the wrapper classes a grid item grows to fit its longest word, which pushes the row wider than the page at phone width. **Fixed** with `min-w-0 wrap-anywhere`, measured above.

**2. Type fields rendered by the UI.** `StatProps` has two fields.

| Field | Renders in |
|---|---|
| `value` | the first `<p>`, when not blank |
| `label` | the second `<p>`, when not blank |

Both render. Neither is on the live page today, because nothing imports the block until #44.

**3. Permission gates per route.** Not applicable. The site has one static route, `/`, with no service calls and no auth. The new module reads no request API, so the route stays prerendered.
